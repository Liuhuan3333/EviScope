# Argument Map

## 科学张力

现有 diff-only safeguard 可以有效判断评论是否与给定 diff 对齐，但真实代码审查的决定性证据可能位于变更文件、仓库依赖、测试或 PR 意图中。直接扩大上下文又可能增加成本和噪声。因此，问题不是“是否提供更多上下文”，而是“何时证据不足、应检索什么、何时停止并弃权”。

## 中心研究问题

在不显著提高错误接受率的前提下，按需证据升级能否减少 diff-only 代码审查验证器对有效评论的错误拒绝？

## 中心假设

把 `INSUFFICIENT` 与 `CONTRADICTED` 分离，并只对证据不足的原子主张执行受限检索，将优于 diff-only 判断和无差别全文上下文。

## 支撑论证

1. 构念论证：diff 对齐和仓库事实有效性不同。限制：必须通过真实样本的证据层级分布证明差异不是边缘现象。
2. 方法论证：三态判断保留不确定性，避免把不可证当作错误。限制：INSUFFICIENT 必须绑定明确证据宇宙和预算。
3. 系统论证：符号和关系驱动检索可能以较小上下文找到决定性证据。限制：跨语言静态分析不稳定，必须与简单 lexical/embedding 基线比较。
4. 可靠性论证：弃权可以将系统部署问题表述为风险—覆盖率权衡。限制：低风险可能只是通过大量弃权获得，因此必须联合报告覆盖率。

## 主要反对意见

- “这只是 ContextCRBench 的另一种上下文实验。”回应：主要单位是原子主张，标签包含三态、证据位置和最低证据层级，主要终点是 safeguard 的错误拒绝及选择性风险。
- “这只是 HalluJudge 加 RAG。”回应：若数据不能证明任务构念差异，该批评成立，项目应停止。
- “最低充分证据是主观的。”回应：使用嵌套证据包、双人独立标注、仲裁和一致性报告；无法达到阈值则停止该主张。
- “仓库本身也不能证明缺陷不存在。”回应：INSUFFICIENT 被定义为在冻结证据宇宙与预算内不可裁决，而不是现实世界中的绝对真假。
- “提升来自更强模型。”回应：所有方法在同一 judge 模型内配对比较，并跨至少三类模型重复。

## 最终论证动作

只有当 beyond-diff 有效主张具有可测规模、diff-only judge 对其产生系统性错误拒绝、且 EviScope 在受控成本下恢复这些评论而不明显增加错误接受时，论文主张才成立。
