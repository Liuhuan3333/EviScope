## Restored paper object (not agent-first)

Working object for FSE:

> A **claim-level, review-time evidence verification task** with human gold, a **measurement study** of diff-only safeguard construct error, and a **budget-constrained targeted evidence-escalation method** (EviScope) for code-review comments.

FSE reviewers care about:

1. a new, rigorous empirical task and benchmark;
2. evidence that diff-only verification systematically mis-handles beyond-diff valid claims;
3. a simple, reproducible escalation method with strong baselines and clustered statistics.

The method may use tools and a stop policy internally, but the **paper contribution is not “we built an agent.”** Agentic framing was a SANER-track packaging choice and is **not** the FSE primary story.

## Revised FSE sprint scope (44-day realistic target)

Original plan target (8 repos, ~400 claims, natural+challenge) is **not** achievable by 2026-10-02. The restored FSE sprint uses a **pre-registered shrink** that still targets a credible full paper:

### Dataset (challenge-first)

- **Primary corpus:** the frozen 4-repo, 48-comment blinded pilot (`stage-s-pilot-candidate-v0.1`).
- **Role:** pre-registered **Challenge set** for method comparison and construct measurement.
- **Do not claim** natural prevalence from this sample.
- **Language:** Python-only for this submission window (Java deferred to threats / future work).
- **Claim target:** all MATERIAL claims from adjudicated Stage S; report attrition honestly. Do **not** cherry-pick high-density comments after labeling.

### Research questions (FSE ordering)

**Primary (must have results):**

- **RQ2:** Does a diff-only judge produce higher false rejection on beyond-diff gold `SUPPORTED` claims than on L0-sufficient claims?
- **RQ3:** Does EviScope targeted escalation reduce beyond-diff false rejection versus diff-only and token-matched full-context / top-k RAG, without materially increasing false acceptance?

**Secondary (include if gold/time allow; otherwise exploratory):**

- **RQ1:** Distribution of minimum evidence level `L*` on the challenge set (descriptive, not prevalence).
- **RQ4:** Risk–coverage from three-way verdicts + abstain rule (paired with coverage, not standalone).

### Method (EviScope MVP — not multi-agent)

Modules to implement for FSE:

1. frozen-claim input (from adjudicated Stage S);
2. nested evidence packages L0→L3 builder on existing snapshots;
3. progressive verifier (三态 + stop at first decisive level);
4. deterministic retrieval planner (symbol/path/test/PR-issue links);
5. trace logging for reproducibility (artifact IDs + hashes, not agent theater).

**Not required for FSE credibility:** ReAct loops, multi-agent orchestration, autonomous planning prose.

### Baselines (minimum matrix)

Same judge model, paired on identical frozen claims:

- B0/B1: diff-only direct + HalluJudge-style if artifact available;
- B3: token-matched changed-file / full-context;
- B4/B5: lexical and embedding top-k + judge;
- B6: oracle gold evidence + judge (mechanism check);
- P: EviScope targeted escalation.

Run **oracle-claim** before end-to-end if automatic segmentation is not frozen in time.

### Statistical reporting

- Unit: claim, clustered by PR/repo;
- Primary endpoint: absolute reduction in false rejection on beyond-diff gold `SUPPORTED` claims;
- Safety endpoint: false acceptance on `CONTRADICTED` and terminal `INSUFFICIENT`;
- Report CIs; do not rely on p-values alone.

## Scientific stop conditions

Same as original FSE plan:

1. No third-person adjudicator.
2. Beyond-diff `SUPPORTED` claims too rare after attrition.
3. Oracle evidence does not improve judge over diff-only (mechanism failure).
4. Targeted escalation does not beat strong full-context / top-k at matched budget.
5. Review-time leakage or gold independence cannot be defended.
